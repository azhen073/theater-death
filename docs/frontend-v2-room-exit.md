# 房间退出对齐（2026-09-19）

本次将 GitHub main `596a171` / `c36e8d1` 的终局退出体验与新版账号、原房间连续对局结合。用户确定：保留局中暂离；终局最后正式玩家退出后立即关闭房间，剩余观众同时退出。注册简化另行实施。

## 各阶段行为

| 阶段 | 退出入口与行为 | 房主及房间生命周期 |
| --- | --- | --- |
| 大厅 | 离开房间，释放名额，保持账号登录 | 房主退出即**解散整房**（所有成员回入口页）；普通成员离开后按在线正式成员规则继任房主，无正式成员后5分钟清理 |
| 局中 | 房间管理 → 暂离对局；保持本局玩家身份和席位，回来恢复本人，计时和行动窗口不暂停 | 房主暂离**不解散**，由其他在线正式成员接任房主；不通过暂离终止对局；无正式成员后仍有5分钟恢复期；离线本身不算退出 |
| 终局复盘 | 复盘页直接离开房间，也保留房间管理入口；返回首页而不退出账号 | 房主退出按**普通离开**处理（房间保留、其他人继续复盘，房主由其他在线正式成员继任）；普通成员退出后其他人可继续复盘；最后正式成员退出后立即解散并通知剩余观众 |

终局退出者仍可在房间存在且本局复盘未结束时用原账号回来查看；这保留新版恢复能力，不采用旧版“退出后永远无法回看”的提示。最后一名正式成员退出后，旧房间码失效，不能重入。

房主“结束复盘，返回大厅”与“离开房间”分别展示：前者将当前成员一起带回原大厅，保留房间码和规则，重新准备和分配身份；后者在复盘阶段**由房主发起时即解散整房**（其他成员的复盘同时关闭），非房主退出则只退出本人。没有在线继任者时暂时无房主，之后按现有规则恢复。

**2026-09-20 变更（任意阶段解散 + 房主离开即解散）**

- `POST /rooms/:code/dissolve` 仅房主可用，且**不再限制大厅阶段**：大厅与复盘直接关闭房间；对局进行中会立即终止本局——未产生胜负的对局按 `aborted` 记入审计（与空房到期同一口径），并广播 `control{dissolved}` 给房间内所有成员（含观众），同时关闭媒体房间。
- `/leave` 语义：房主在**大厅**退出即解散整房（响应 `{left:true, dissolved:true, seatRetained:false}`）；房主在**对局进行中**退出是「暂离」（响应 `{left:true, dissolved:false, seatRetained:true}`，席位与计时保留、房主由其他在线正式成员接任）；房主在**复盘**退出是**普通离开**（响应 `{left:true, dissolved:false}`，房间保留、其他人继续复盘、房主同样继任）。非房主一律按普通离开处理。空置导致房间被关闭时，回执的 `seatRetained` 归 `false`。
- 因此「无正式成员的大厅」不再可达（房主退出即解散），5 分钟空房 TTL 只对**对局中全员暂离**后的房间生效。
- 旧的契约夹具（`tests/fixtures/contract-2.1/*.json`）仍记录 `dissolve.reason='lobby_required'` 的历史取值；夹具只做 schema 校验，需按正规流程用 `EXPORT_CONTRACT_FIXTURES` 重新导出后才与新行为一致。

## 实现边界与接口

- `/leave` 继续使用 `requestId`；响应为 `{left:true, dissolved:boolean, seatRetained:boolean}`（`dissolved` 为 2026-09-20 新增，与旧版入口的 `/leave` 形状一致），房间已关闭时不返回保留席位的误导信息。
- HTTP 成功或实时终端通知后才离开页面；响应丢失保留原意图，重试使用同一请求ID及载荷，不调用登出或结束复盘接口。
- 退出确认文案按大厅、进行中、复盘以及观战身份区分，复盘不再显示“对局继续计时”。
- 终局无正式成员清理取消旧空房定时器，保留已完成对局审计记录，撤销剩余观众的访问；不清理账户数据库。
- 房间销毁后不再重新注册该局的媒体授权，避免已经撤销的语音房间状态残留。
- 没有合并或改写旧版退出实现；新版通过自己的成员、授权、继任及幂等机制满足对齐后的行为。
